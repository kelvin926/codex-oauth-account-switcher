# v0.6.3

Lunarwerx 원본 사이트에 있는 최신 초기화 예고가 앱에서 빠지고, 평균 대기 수치가 다르게 보이던 문제를 수정했습니다.

## 수정 내용

- 사이트가 화면에 사용하는 공개 피드에서 최신 Tibo 게시물을 가져옵니다. 초기화 예고와 관련 공지를 게시물 작성 시각 순서로 보여줍니다. 예고 글을 실제 초기화 횟수에 합산하지 않습니다.
- 평균 대기는 사이트의 최근 30일 기준으로 맞췄습니다. 30일 동안 9회면 3.3일입니다. 기존 3.6일은 최근 120일의 완료된 간격 평균이었으며, 출처 설명에서 따로 확인할 수 있습니다.
- 확률은 사이트처럼 정수로 반올림합니다. 예를 들어 49.1%는 49%, 6.8%는 7%로 표시됩니다. 원본 확률과 알림 판단값은 유지합니다.
- 예측 갱신 시각을 바로 표시하고 마지막 초기화 기록 시각과 구분합니다. 한 번의 갱신 실패를 곧바로 오래된 데이터로 표시하던 문제를 수정했습니다.
- 캐시 파일 저장 실패가 새 소식 조회를 막지 않게 했습니다. 캐시를 저장하지 못하면 다음 실행에서 새로 가져옵니다.
- 긴 게시물은 더 보기로 펼치고, 과거 게시물과 초기화 기록은 접어서 가독성과 스크롤 부담을 개선했습니다.

## 갱신과 알림

5분 간격과 서버의 재시도 대기 시간을 지킵니다. HTTP 캐시를 재사용하지 않고, 사이트와 같은 5분 단위 피드 주소를 사용합니다. 창이 다시 표시되면 다음 갱신 가능 시각을 확인합니다. 최초 실행 시 과거 공지가 한꺼번에 알림으로 뜨지 않으며, 새 예고 글은 완료 기록과 다른 알림으로 표시합니다.

사이트 피드는 버전이 없는 공개 형식이므로, 형식이 바뀌거나 사용할 수 없으면 문서화된 v1 API로 예측과 초기화 기록을 조회합니다. 이때 최신 Tibo 피드를 불러오지 못했다는 안내를 표시합니다. 오래되거나 이전 시점의 응답을 새 데이터로 처리하지 않습니다. 이 예상은 OpenAI의 확정 일정이나 내 계정의 정기 초기화 시각이 아닙니다.

## 검증

공개 피드의 실제 응답 필드를 확인하고 예고와 완료 기록 분리, 중복 알림 방지, 구버전 캐시 호환, API 대체 조회, 갱신 실패와 오래됨 구분, 캐시 저장 실패 경로를 검사합니다. Windows 전체 테스트와 자동 시작 등록 검사, 패키지 EXE의 계정/분석/예측/소식 화면 촬영이 성공한 뒤 배포합니다.
